1. Visão Geral do Sistema

1.1 Objetivo

O Portal de Agendamento de Planos de Trabalho é uma aplicação web desenvolvida para gerir o planeamento, submissão, aprovação e acompanhamento de planos de trabalho em autoestradas. O sistema permite a coordenação entre prestadores de serviços, gestores operacionais, coordenadores de operações e administradores.

1.2 Âmbito

O sistema abrange:

  • Criação e submissão de planos de trabalho por prestadores de serviços
  • Aprovação e rejeição de planos por gestores operacionais
  • Visualização de calendário com planos aprovados
  • Gestão de atividades e períodos de trabalho
  • Controlo de acessos baseado em perfis de utilizador
  • Dashboard administrativo para gestão de dados

1.3 Tipos de Utilizadores

Perfil Email de Acesso Descrição
Prestador de Serviços prestador@teste.pt Cria e submete planos de trabalho, edita planos rejeitados ou aprovados
Gestor Operacional (GO) go@teste.pt Aprova ou rejeita planos, remove aprovações, visualiza calendário
Coordenador de Operações (CCO) cco@teste.pt Visualiza dashboard com estatísticas e relatórios
Administrador admin@teste.pt Gere dados mestres (concessões, autoestradas, tipos de trabalho, etc.)

2. Funcionalidades por Perfil de Utilizador

2.1 Prestador de Serviços

2.1.1 Criação de Plano de Trabalho

O prestador pode criar um novo plano de trabalho preenchendo os seguintes campos:

Cabeçalho do Plano:
  • Concessão: Seleção da concessão (ex: Ascendi, Brisa, etc.)
  • Auto Estrada: Seleção da autoestrada (filtrada pela concessão selecionada)
  • Km Inicial: Quilómetro inicial do plano
  • Km Final: Quilómetro final do plano
  • Sublanço: Identificador do sublanço (calculado automaticamente ou inserido manualmente)
  • Tipo de Trabalho: Categoria do trabalho (ex: PAVIMENTOS, TALUDES, SINALIZAÇÃO HORIZONTAL, etc.)
  • Atividade: Atividade específica dentro do tipo de trabalho (filtrada pelo tipo selecionado)
  • Urgente: Checkbox para marcar planos urgentes
Características do Trabalho:
  • Trabalho Fixo: Checkbox para trabalhos em local fixo
  • Trabalho Móvel: Checkbox para trabalhos móveis
  • Perigos Temporários: Checkbox para trabalhos com perigos temporários
Contactos:

O sistema requer informações de contacto para três entidades:

  • Fiscalização: Nome e contacto do responsável pela fiscalização
  • Entidade Executante: Nome e contacto da entidade que executa o trabalho
  • Sinalização: Nome e contacto do responsável pela sinalização

2.1.2 Gestão de Atividades

Cada plano pode conter múltiplas atividades. Para cada atividade, o prestador define:

  • Descrição da Atividade: Texto descritivo da atividade
  • Período: Data de início e fim da atividade (seleção de intervalo de datas)
  • PK Inicial: Ponto quilométrico inicial (formato: X Km + Y m)
  • PK Final: Ponto quilométrico final (formato: X Km + Y m)

2.1.3 Detalhes Diários

Para cada dia dentro do período de uma atividade, o prestador pode especificar:

  • Hora de Início: Hora de início do trabalho (formato 24h: HH:MM)
  • Hora de Fim: Hora de fim do trabalho (formato 24h: HH:MM)
  • Todo o Dia: Checkbox para trabalhos que ocupam o dia inteiro (00:00 - 23:59)
  • PK Inicial e Final: Pontos quilométricos específicos para o dia
  • Perfil: Perfil de trabalho (ex: 1 x 1, 1 x 2, 2 x 2, etc.)
  • Restrições: Seleção múltipla de restrições (filtradas pelo perfil selecionado)
  • Sentido: Sentido do trabalho (crescente, decrescente, ambos)
  • Tipo de Trabalho: Tipo específico para o dia
  • Local da Intervenção: Local específico da intervenção
  • Esquema: Esquema de sinalização (filtrado pelo tipo de trabalho)
  • Observações: Campo de texto livre para observações
Validações Automáticas:
  • A hora de fim deve ser posterior à hora de início
  • O formato das horas deve ser HH:MM (24 horas)
  • Pelo menos uma atividade deve ser adicionada antes da submissão
  • O sublanço é calculado automaticamente com base nos Km inicial e final

2.1.4 Submissão de Plano

Após preencher todos os campos obrigatórios e adicionar pelo menos uma atividade, o prestador pode submeter o plano. O plano fica com o status:

Pendente Aprovação

2.1.5 Edição de Planos

O prestador pode editar planos nos seguintes estados:

  • Pendente Aprovação: Edição livre, mantém o status após resubmissão
  • Rejeitado: Edição livre, muda para "Pendente Aprovação" após resubmissão
  • Aprovado (Confirmado): Edição permitida, muda para "Editado - Pendente Aprovação" após resubmissão
Importante: Quando um plano aprovado é editado e resubmetido, ele volta para a fila de aprovação com o status Editado - Pendente Aprovação e requer nova aprovação do Gestor Operacional.

2.1.6 Visualização de Planos

O prestador pode visualizar todos os seus planos submetidos na secção "Todos os Agendamentos", onde pode ver:

  • Lista de todos os planos com status
  • Número de atividades por plano
  • Comentários do Gestor Operacional (em caso de rejeição)
  • Botão "Editar" para planos editáveis

2.2 Gestor Operacional (GO)

2.2.1 Aprovação de Planos

O GO tem acesso a um separador dedicado "Aprovação de Planos" onde pode:

  • Visualizar todos os planos com status "Pendente Aprovação" ou "Editado - Pendente Aprovação"
  • Ver detalhes completos de cada plano (cabeçalho, contactos, atividades, detalhes diários)
  • Aprovar planos (muda status para Aprovado)
  • Rejeitar planos com comentário obrigatório (muda status para Rejeitado)
Processo de Aprovação:
  1. GO clica em "Ver Detalhes" para analisar o plano completo
  2. Revisa todas as informações (cabeçalho, contactos, atividades, períodos)
  3. Clica em "Aprovar" ou "Rejeitar"
  4. Se rejeitar, deve inserir um comentário explicativo
  5. Confirma a ação no diálogo de confirmação
  6. O prestador é notificado da decisão

2.2.2 Remoção de Aprovação

O GO tem a capacidade exclusiva de remover aprovações de planos já aprovados:

  • Na secção "Todos os Agendamentos", planos aprovados mostram o botão "Remover Aprovação"
  • Este botão é visível apenas para o perfil GO (go@teste.pt)
  • Ao clicar, abre um diálogo solicitando o motivo da remoção
  • Após confirmação, o plano volta ao status "Pendente Aprovação"
  • O motivo da remoção é guardado no campo comentarioGO

2.2.3 Visualização de Calendário

O GO tem acesso a um calendário interativo que mostra:

  • Todos os planos aprovados organizados por data
  • Indicadores visuais para dias com planos agendados
  • Detalhes dos planos ao clicar em cada dia
  • Informações de PK, perfil, restrições, sentido, tipo de trabalho, local e esquema

2.3 Coordenador de Operações (CCO)

O CCO tem acesso a um dashboard com:

  • Estatísticas gerais de planos (total, pendentes, aprovados, rejeitados)
  • Visualizações gráficas de dados
  • Relatórios de atividades por período
  • Análise de desempenho e métricas operacionais

2.4 Administrador

O administrador tem acesso a um painel de gestão de dados mestres onde pode:

  • Gerir concessões (adicionar, editar, remover)
  • Gerir autoestradas e associações com concessões
  • Gerir tipos de trabalho e atividades associadas
  • Gerir perfis e restrições
  • Gerir esquemas de sinalização
  • Importar/exportar dados em formato CSV

3. Estados e Fluxos de Trabalho

3.1 Estados de um Plano

Estado Descrição Ações Disponíveis
Pendente Aprovação Plano submetido aguardando aprovação do GO Prestador: Editar
GO: Aprovar, Rejeitar
Aprovado Plano aprovado pelo GO e agendado no calendário Prestador: Editar (volta para "Editado - Pendente Aprovação")
GO: Remover Aprovação
Rejeitado Plano rejeitado pelo GO com comentário Prestador: Editar e resubmeter (volta para "Pendente Aprovação")
Editado - Pendente Aprovação Plano anteriormente aprovado que foi editado e resubmetido Prestador: Editar
GO: Aprovar, Rejeitar

3.2 Fluxo de Trabalho Principal

  1. Criação: Prestador cria novo plano de trabalho
  2. Adição de Atividades: Prestador adiciona uma ou mais atividades com períodos e detalhes
  3. Preenchimento de Detalhes Diários: Para cada dia de cada atividade, prestador preenche horários e especificações
  4. Submissão: Prestador submete o plano (status: Pendente Aprovação)
  5. Revisão: GO revisa o plano na fila de aprovação
  6. Decisão:
    • Se Aprovar: Plano fica com status "Aprovado" e aparece no calendário
    • Se Rejeitar: Plano fica com status "Rejeitado" e prestador recebe comentário
  7. Pós-Aprovação:
    • Prestador pode editar plano aprovado (volta para "Editado - Pendente Aprovação")
    • GO pode remover aprovação (volta para "Pendente Aprovação")

3.3 Fluxo de Edição de Plano Aprovado

  1. Prestador clica em "Editar" num plano com status "Aprovado"
  2. Sistema carrega todos os dados do plano no formulário
  3. Sistema marca internamente que está a editar um plano aprovado (isEditingApprovedPlan = true)
  4. Prestador faz as alterações necessárias
  5. Prestador clica em "Submeter Plano de Trabalho"
  6. Sistema muda o status para "Editado - Pendente Aprovação"
  7. Plano aparece na fila de aprovação do GO para nova revisão
  8. GO aprova ou rejeita o plano editado

5. Regras de Negócio

5.1 Validações de Formulário

  • Todos os campos obrigatórios devem ser preenchidos antes da submissão
  • Pelo menos uma atividade deve ser adicionada ao plano
  • O formato das horas deve ser HH:MM (24 horas)
  • A hora de fim deve ser posterior à hora de início
  • O PK final deve ser maior que o PK inicial
  • O Km final deve ser maior ou igual ao Km inicial

5.2 Cálculo Automático de Sublanço

O sublanço é calculado automaticamente com base nos campos:

  • Auto Estrada selecionada
  • Km Inicial e Km Final

Formato: [AutoEstrada] - Cidade [KmInicial] - Cidade [KmFinal]

5.3 Filtragem de Opções

  • Autoestradas: Filtradas pela concessão selecionada
  • Atividades: Filtradas pelo tipo de trabalho selecionado
  • Restrições: Filtradas pelo perfil selecionado
  • Esquemas: Filtrados pelo tipo de trabalho do dia

9. Casos de Uso Detalhados

9.1 UC01 - Criar e Submeter Plano de Trabalho

Ator Principal: Prestador de Serviços

Pré-condições: Utilizador autenticado como Prestador

Fluxo Principal:

  1. Prestador acede ao formulário de criação de plano
  2. Seleciona a concessão
  3. Seleciona a autoestrada (filtrada pela concessão)
  4. Insere Km inicial e Km final
  5. Sistema calcula automaticamente o sublanço
  6. Seleciona tipo de trabalho
  7. Seleciona atividade (filtrada pelo tipo)
  8. Marca checkboxes de características (trabalho fixo/móvel, perigos temporários)
  9. Preenche contactos (fiscalização, entidade executante, sinalização)
  10. Clica em "Adicionar Atividade"
  11. Preenche descrição da atividade
  12. Seleciona período (data início e fim)
  13. Insere PK inicial e final da atividade
  14. Para cada dia do período, preenche detalhes diários
  15. Clica em "Guardar Atividade"
  16. Repete passos 10-15 para adicionar mais atividades (opcional)
  17. Clica em "Submeter Plano de Trabalho"
  18. Sistema valida todos os campos
  19. Sistema cria plano com status "Pendente Aprovação"
  20. Sistema apresenta notificação de sucesso
  21. Sistema limpa o formulário

Pós-condições: Plano criado e visível na fila de aprovação do GO

9.2 UC02 - Aprovar Plano de Trabalho

Ator Principal: Gestor Operacional

Pré-condições: Utilizador autenticado como GO, existe pelo menos um plano pendente

Fluxo Principal:

  1. GO acede ao separador "Aprovação de Planos"
  2. Visualiza lista de planos pendentes
  3. Clica em "Ver Detalhes" num plano
  4. Revisa cabeçalho, contactos e atividades
  5. Clica em "Aprovar"
  6. Sistema apresenta diálogo de confirmação
  7. GO confirma a aprovação
  8. Sistema muda status do plano para "Aprovado"
  9. Sistema adiciona plano ao calendário
  10. Sistema apresenta notificação de sucesso

Pós-condições: Plano aprovado e visível no calendário

9.3 UC03 - Rejeitar Plano de Trabalho

Ator Principal: Gestor Operacional

Pré-condições: Utilizador autenticado como GO, existe pelo menos um plano pendente

Fluxo Principal:

  1. GO acede ao separador "Aprovação de Planos"
  2. Visualiza lista de planos pendentes
  3. Clica em "Ver Detalhes" num plano
  4. Identifica problemas no plano
  5. Clica em "Rejeitar"
  6. Sistema apresenta diálogo solicitando comentário
  7. GO insere motivo da rejeição
  8. GO confirma a rejeição
  9. Sistema muda status do plano para "Rejeitado"
  10. Sistema guarda comentário no campo comentarioGO
  11. Sistema apresenta notificação de sucesso

Pós-condições: Plano rejeitado, prestador pode visualizar comentário e editar

9.4 UC04 - Editar Plano Aprovado

Ator Principal: Prestador de Serviços

Pré-condições: Utilizador autenticado como Prestador, existe plano com status "Aprovado"

Fluxo Principal:

  1. Prestador acede à secção "Todos os Agendamentos"
  2. Localiza plano aprovado que deseja editar
  3. Clica em "Editar"
  4. Sistema carrega dados do plano no formulário
  5. Sistema marca internamente que está a editar plano aprovado
  6. Prestador faz alterações necessárias
  7. Prestador clica em "Submeter Plano de Trabalho"
  8. Sistema valida alterações
  9. Sistema muda status para "Editado - Pendente Aprovação"
  10. Sistema apresenta notificação informando nova submissão
  11. Plano volta para fila de aprovação do GO

Pós-condições: Plano editado aguarda nova aprovação

9.5 UC05 - Remover Aprovação de Plano

Ator Principal: Gestor Operacional

Pré-condições: Utilizador autenticado como GO (go@teste.pt), existe plano aprovado

Fluxo Principal:

  1. GO acede à secção "Todos os Agendamentos"
  2. Localiza plano aprovado
  3. Clica em "Remover Aprovação"
  4. Sistema apresenta diálogo solicitando motivo
  5. GO insere motivo da remoção
  6. GO confirma a remoção
  7. Sistema muda status para "Pendente Aprovação"
  8. Sistema guarda motivo no campo comentarioGO
  9. Sistema remove plano do calendário
  10. Sistema apresenta notificação de sucesso

Pós-condições: Plano volta para estado pendente, requer nova aprovação

12. Glossário

Termo Definição
PK (Ponto Quilométrico) Referência de localização numa autoestrada, expressa em quilómetros e metros
Sublanço Segmento específico de uma autoestrada delimitado por dois pontos quilométricos
GO (Gestor Operacional) Utilizador responsável por aprovar ou rejeitar planos de trabalho
CCO (Coordenador de Operações) Utilizador com acesso a dashboards e relatórios gerenciais
Perfil Configuração de vias numa autoestrada (ex: 2x2 significa duas vias em cada sentido)
Restrições Limitações ou condições aplicáveis a um trabalho (ex: berma, via de trânsito)
Esquema Configuração de sinalização temporária para o trabalho
Sentido Direção do tráfego (crescente, decrescente ou ambos)
Atividade Tarefa específica dentro de um plano de trabalho, com período e localização definidos
Detalhes Diários Especificações de horário e configuração para cada dia de uma atividade
